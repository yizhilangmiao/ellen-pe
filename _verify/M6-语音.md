# M6 语音链（第一版：朗读 + 录音转文字）

> 写于 2026-11-04 · APK `0.3.0-m6` / 9,011,783 B / 12 个自有插件 → **13 个**（新增 `EllenAudio`）
> 设备：MuMu 实例 2（Android 15 / 127.0.0.1:16448 / 360×616 CSS）

## 一、旧包这一块原来是什么

从 `dexwork\smali-b17` + `work\assets\public\assets` 反出来的四条事实：

| 用途 | 旧包实现 | 结论 |
|---|---|---|
| 本地转写 | `EllenLocalSpeechPlugin`（62 KB）+ `local-asr/model.int8.onnx` 239 MB + `local-vad/silero_vad.onnx` + onnxruntime-android | **发布的轻量包里没带模型资产**（`work\assets\public` 下无 `local-asr`，`so count 0`），实际不可用 |
| 云端朗读 | minimax `speech-2.8-hd` / `speech-2.8-turbo`，`https://api.minimax.cn` / `api.minimax.io`，走 `EllenVoiceHttp.requestStream` 拿 PCM | 需要 minimax 的 key，且要自己解 PCM 播放 |
| 录音 | `EllenAudio.startRecording{recordingId,fileId}` → 16 kHz mono s16le → 32,000 字节分块喂 `transcribe` | 采样格式与分块大小是硬约定 |
| 朗读的 fallback | 无 | 旧包没有系统 TTS 兜底 |

**决定（第一版）**：
1. 朗读走 **Android 系统 TTS**：零配置、离线、装完就能念，不花 token 不联网。
2. 转写走 **OpenAI 兼容 `/v1/audio/transcriptions`**，默认预设硅基流动 `FunAudioLLM/SenseVoiceSmall`（有免费额度），key 存系统密钥库。
3. 本地 SenseVoice（239 MB + onnxruntime）押后 —— 老大实际发的包本来就没这玩意，先不背这个体积。

## 二、原生：`EllenAudio`（新插件，13 号）

`app\app\src\main\java\cn\ellen\companion2\plugin\EllenAudioPlugin.kt`

| 方法 | 行为 |
|---|---|
| `capabilities()` | `{record:true, play:false, callPcm:false, transcribe:true, sampleRate:16000, channels:1, maxDurationMs:600000}` |
| `requestPermission()` | 预先要麦克风权限（切到语音输入时调一次，用户按下就不必等弹窗）。固定回 `{granted:Boolean, asked:Boolean, blocked:Boolean}`：`asked` = 这次有没有真弹窗；已授权直接 `{granted:true, asked:false, blocked:false}`；`blocked` = 系统已经不会再弹窗（详见下面「`blocked` 字段」）。**被拒也 resolve，不 reject** —— 要不要提示「去系统里给录音权限」是界面的事，reject 只会逼调用方再写一个 catch |
| `startRecording({fileId, maxDurationMs})` | 权限不够先走 `requestPermissionForAlias("microphone")`；开工返回 `{fileId, path, sampleRate, channels, startedAt, maxDurationMs}` |
| `stopRecording()` | 停线程 → 补 WAV 头 → 返回 `{fileId, path, bytes, durationMs, sampleRate, channels}`，并 emit `audioEvent {type:'recorded'}` |
| `cancelRecording()` | 停 + 删文件，emit `{type:'cancelled'}` |
| `readRecording({fileId})` | 把 WAV 读成 base64（上限 32 MiB） |
| `releaseRecording({fileId})` | 删掉这一段的文件 |
| `state()` | `{recording, fileId, startedAt, elapsedMs, bytes, sampleRate, channels, lastError}` |

实现要点：
- 用 **`AudioRecord`**（`MediaRecorder.AudioSource.VOICE_RECOGNITION`）而不是 `MediaRecorder` —— 转写要裸 PCM，MediaRecorder 只给 AAC/AMR 容器。
- 落盘是「先占 44 字节、边录边写、收尾回填 WAV 头」，所以录一半被杀也只丢尾巴，不会得到一个坏文件（能播，只是长度按实际字节算）。
- `fileId` 必须匹配 `[A-Za-z0-9._:-]{1,120}`，不匹配就自己生成 `rec-<base36>-<rand>`；一次只允许一段在录（`AUDIO_BUSY`）。
- `maxDurationMs` 夹在 1 s–10 min，默认 120 s。
- `AndroidManifest.xml` 加 `android.permission.RECORD_AUDIO`。
- 2026-11-11 补 `requestPermission`（`@PluginMethod` 7 → 8）：`alreadyGranted()` 走
  `ContextCompat.checkSelfPermission(context, Manifest.permission.RECORD_AUDIO)`，不看 Capacitor 的权限缓存；
  读状态抛异常就按「没授权」处理（宁可多弹一次窗，也不把调用方卡在异常路径上）。
  实测（MuMu 16448 / APK 100,525,319 B）：`pm revoke` 后调 → 真弹「要允许“艾莲”录音吗？」点允许 →
  `{granted:true, asked:true}`；再调 → `{granted:true, asked:false}`；再 revoke 后点「不允许」→
  `{granted:false, asked:true}`，**进程没崩**（pid 32770 前后一致）。

### `blocked` 字段（2026-11-11 22:00 补，返回体 `{granted, asked, blocked}`）

`blocked = !granted && !shouldShowRequestPermissionRationale(...)` —— 即「系统已经不会再弹窗了」，web 只能引导去设置页。

实测五条（MuMu 16448 / APK 100,533,188 B / pid 35814 / CDP 9336）：

| 场景 | 返回体 |
|---|---|
| 清标志 + `pm revoke` → 首次弹窗点「仅在使用该应用时允许」 | `{granted:true, asked:true, blocked:false}` |
| 已授权再调（无弹窗） | `{granted:true, asked:false, blocked:false}` |
| 清标志 + revoke → 第一次点「不允许」 | `{granted:false, asked:true, blocked:false}` |
| 紧接着再调 → 第二次点「不允许」（系统置 `USER_FIXED`） | `{granted:false, asked:true, blocked:true}` |
| `blocked:true` 之后再调第三次 | `{granted:false, asked:true, blocked:true}`，**不再弹窗、也不挂起**，立刻返回 |

两个坑：

1. **`pm revoke` 不会清 `USER_FIXED`**。上一轮拒绝过的话，直接 revoke 再拒绝，第一次就回 `blocked:true`（我第一遍就是这么被误导的）。要测「第一次拒绝」必须先 `pm clear-permission-flags <pkg> android.permission.RECORD_AUDIO user-fixed user-set` 再 revoke；测完同样两步还原 granted，否则后来的人会静默被拒。
2. 判定依据是 `dumpsys package` 里的 `flags=[ USER_SET|USER_FIXED|…]`：出现 `USER_FIXED` 即 `blocked`。

## 八、语音输入：按住说话 + 说完直接发（2026-11-04 晚）

### 为什么不用系统识别

老大问「手机键盘自带语音转文字能不能直接用」。实测这台机器**没有系统识别服务**：

```
adb shell cmd package query-services -a android.speech.RecognitionService
  真机 3422813346000RJ  → No services found
  模拟器 16448          → No services found
adb shell settings get secure voice_recognition_service
  → null
```

→ `SpeechRecognizer` / `RecognizerIntent.ACTION_RECOGNIZE_SPEECH` 在这台机器上**调不动**（没有实现方）。
键盘上的语音键是**输入法私有链路**（IME 内部录音 → 厂商云 ASR → 直接上屏），没有对外 API。
能等价做到的只有「录音 + 云端转写」，也就是我们已有的 `core/recorder.js` + `core/asr.js`。

### 改了什么

| 文件 | 改动 |
|---|---|
| `app\web\src\app\main.js` | 抽 `sendMessage(text)`（键盘与语音共用一条发送路，原来内联在 `onSend` 里）；新增 `handleMic(action)`，`action='start'` 只在未录音时开录、`'stop'` 只在录音中收尾、`'toggle'` 走原开关；转写成功后读 `cfg.autoSend`，为真则清空输入框并直接 `sendMessage(text)` |
| `app\web\src\app\ui\views\chat\chat.js` | 麦克风从 `click` 改成 `pointerdown/pointerup/pointercancel/lostpointercapture`（按下即开录、松手即转写）；`click` 只在没有指针事件时兜底，且带 `pointerHeld` 守卫防重复 |
| `app\web\src\app\ui\views\chat\chat.css` | `.el-composer-mic` 加 `touch-action:none` + `user-select:none` + `-webkit-touch-callout:none`（否则按住会弹系统长按菜单、还会选中文字） |
| `app\web\src\app\core\asr.js` | `DEFAULT_CONFIG` 加 `autoSend:false` |
| `app\web\src\app\ui\views\settings\settings.js` | 「语音输入」卡加第三个按钮「说完直接发出去 / 先填进输入框」；`asrSaveBtn` 保存时带上 `autoSend`（否则一保存就被打回默认） |

### 坑

1. **`click` 与 `pointerdown/up` 会各触发一次** —— 手机上按住再松手，`pointerup` 之后还会补一个 `click`，没有守卫就会「停两次」。用 `pointerHeld` 标志拦住 `click`。
2. **不写 `touch-action:none`，按住会触发系统长按选择**，`pointerup` 可能收不到（被系统抢走手势）。
3. **`setDictation('')` 必须在 `sendMessage` 之前** —— 否则语音文字同时进了输入框又被发出去，界面上留一份残留。
4. `window.__ellen.state` 是函数（`app.state()`），别写成 `.state.messages`。
5. 切页后 `document.querySelector('.el-composer-mic')` 为 null（页面仍是设置页），测试脚本要先用 `.el-nav-item[data-tab=chat]` 点回聊天。

### 还是缺一枚 ASR key

转写要 `/v1/audio/transcriptions`（默认硅基流动 `FunAudioLLM/SenseVoiceSmall`，注册送额度）。
老大手里现在只有 DeepSeek 与 minimax 的 key，两家都不做 ASR，所以端到端「说话→文字→回复」还差这一步。

## 九、离线识别：sherpa-onnx streaming zipformer 中文 14M（int8）

### 为什么自己带模型

这台 vivo **没有系统 `RecognitionService`**：

```
adb shell cmd package query-services -a android.speech.RecognitionService
  → No services found            （真机 3422813346000RJ 与模拟器 127.0.0.1:16448 都是）
adb shell settings get secure voice_recognition_service
  → null
```

键盘上那个语音键是**输入法私有链路**（IME 内部录音 → 厂商云 ASR → 上屏），没有对外 API，
`SpeechRecognizer` / `RecognizerIntent.ACTION_RECOGNIZE_SPEECH` 全都调不动。
所以「离线、不联网、录音不出手机」只能自己打包模型 —— 老大定了 14M 这套（m04477）。

### 装了什么

| 位置 | 内容 | 体积 |
|---|---|---|
| `app\app\src\main\assets\asr\streaming-zipformer-zh-14m\encoder-epoch-99-avg-1.int8.onnx` | encoder | 21,621,684 B |
| 同目录 `decoder-epoch-99-avg-1.int8.onnx` | decoder | 1,888,682 B |
| 同目录 `joiner-epoch-99-avg-1.int8.onnx` | joiner | 1,795,562 B |
| 同目录 `tokens.txt` | 词表 | 48,697 B |
| `app\app\libs\sherpa-onnx-2.0.1.aar` | 引擎（含 onnxruntime + arm64-v8a / x86_64 两套 so） | 47.2 MB |

- `app\app\build.gradle.kts`：`implementation(files("libs/sherpa-onnx-2.0.1.aar"))`；`abiFilters += listOf("arm64-v8a","x86_64")`；**`noCompress += listOf("onnx")`** —— sherpa 走 `AAssetManager` 直接拿文件描述符，onnx 被 aapt 压过就读不了。
- 模型来源：`huggingface.co` 直连 TLS 超时、`github.com` 直连 60 s 拿不到 1 MB；**`hf-mirror.com` 可通（约 830 KB/s）**，GitHub 走 `https://gh-proxy.com/<原 url>` 可达 **2.93 MB/s**（`ghproxy.net` 23 KB/s，`ghfast.top` 403，`mirror.ghproxy.com` SSL 失败）。文件现放在 `_下载\sherpa\`。
- APK 变化：`0.3.0-m6` 从 5,901,624 B → **98,604,558 B**（assets 24.2 MB + arm64 so 30.0 MB + x86_64 so 34.0 MB；x86_64 只为模拟器，发版按 ABI 拆包后单设备约 54 MB）。

### 原生 `EllenLocalSpeechPlugin.kt`（第 14 个插件）

契约照旧包 `EllenLocalSpeech`（4 方法 + 我们自加 1）：`state()` / `transcribe({base64})` / `ready({sessionId,requestId})` / `cancel()` / `close()`。

- `state()` → `{available, loading, model:"streaming-zipformer-zh-14m-int8", sampleRate:16000, lastError}`。
- `transcribe({base64})`：base64 WAV → `decodeWav()` 解 PCM s16le → FloatArray（-1..1）→ 单线程 `runRecognizer()`：
  ```kotlin
  stream.acceptWaveform(samples, SAMPLE_RATE)
  stream.acceptWaveform(FloatArray((SAMPLE_RATE * 0.3f).toInt()), SAMPLE_RATE)  // 尾部补 0.3 s 静音
  stream.inputFinished()
  while (engine.isReady(stream)) engine.decode(stream)
  engine.getResult(stream).text.trim()
  ```
  返回 `{text, ms, samples, model}`。`MAX_SAMPLES = 16000*300`（5 分钟上限，再多就是误触）。
- 引擎懒加载（第一次 `transcribe` 才 init，避免拖慢启动），失败只写 `lastError`，不崩。

### web 侧（`app\web\src\app\core\asr.js`）

- `PLATFORMS` 最前面加 `{id:'local', label:'离线识别'}`，**`DEFAULT_CONFIG.platform` 改为 `'local'`**。
- `isUsable(cfg)`：`platform === 'local'` 直接 true（不需要 key）。
- 新增 `localState()` / `transcribeLocal({base64})`。
- `transcribe()` 分派：本地 → 失败时若 vault 里有云端 key 就**自动退到云端**再试一次（离线识别空结果/模型坏掉都不会让按住说话这条路彻底哑掉）；云端平台的逻辑抽成 `transcribeCloud({fileId, base64, cfg})`。

### 已知短板

1. **没有标点**：14M 这套不带标点模型，输出是「今天外面下雨了你带伞了吗」。不自动补：补错了比没有更难受，落进输入框让老大自己加。
2. **偶尔重复一个字**（`关关`）：streaming zipformer 在 chunk 边界的通病。不做「去重复字」的后处理 —— 中文本身合法叠字太多（看看/慢慢/常常），规则化必然误伤。
3. **准确率低于云端**：同一句用硅基流动的 SenseVoice 是**一字不差**（`_临时\m6-asr-real.js` 实测）。所以云端那条路留着，`transcribe()` 会自动兜底。

## 十一、声音克隆：已复刻成功（2026-11-10）

### 一、链路（web 直连 minimax，不经原生）

1. `fetch('./voice-clone/ellen-reference.mp3')` —— 软件内置的艾莲原声，1,205,325 B，随包发布（`app\web\public\voice-clone\`）。
2. `POST https://api.minimax.cn/v1/files/upload?GroupId=` —— `FormData`：`purpose=voice_clone`、`file`（文件名必须带 `.mp3`，服务端按扩展名判类型）。
3. `POST https://api.minimax.cn/v1/voice_clone` —— `{file_id: Number, voice_id: 'ellen_'+32hex, model: 'speech-2.8-hd'}`。
4. 落盘：localStorage `ellen.voice.clone.v1 = {voiceId, model, at, fileId}`，并 `writePrefs({provider:'minimax', voiceId})`；设置页「音色 id」自动填上。

`core/voice-clone.js` 的错误码映射（全部实测过头两条）：2038 未实名 / 1008·402 余额不足 / 2049·1004·401·403 key 不对 / 1026·1027 素材审核 / 2013 参数 / 1002·1039·1041·2045·429 频繁。

### 三、坑（这次踩的）

1. **scope `tts` 里存了 JSON**（`{"apiKey":"sk-…"}`）→ `Authorization: Bearer {"apiKey":…}` → 平台 401，界面只说「这个 key 不对」，查了很久。修：`core/speech.js` 的 `readKey()` 见到 `{` 开头的值就 `JSON.parse` 取 `.apiKey`，否则原样 `trim()`。
2. **`EllenSecureConfig` 的方法是 `read/write/remove`**（不是 `get/set`），`write({scope:'tts', value:'sk-…'})` 要传裸 key 字符串。
3. **状态行 / 说明行要跟着「正在用哪种朗读」说话**：模拟器没有系统 TTS，原来标题右侧一直写「这台机器没有中文朗读引擎」，即使正在用云端音色也这么写，看起来像念不了。现在 provider=minimax 时显示「云端音色 · 已复刻 / 内置」，说明行也换成云端那句。
4. **每次复刻都收费**（minimax 按音色一次性收费，约 9.90 元）。所以 `cloneVoice` 先看 `ellen.voice.clone.v1`，有就直接复用（`res.reused`），不重复扣费。

### 四、还没做

- 复刻失败时没有「换个素材」入口（现在只能用内置那支）。
- 音色 id 只校验非空，没校验存在性 —— 填错会在念的时候才报 `TTS_FAILED`。
- 「已复刻」与「内置」靠 `voiceId !== 'female-shaonv'` 判断，用户手输别的内置音色 id 会被误判成已复刻。
