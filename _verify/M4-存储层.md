# M4 · 存储层与数据迁移（v0.3.0-m4）

> 目标：聊天能落库、重启不丢；旧包导出的 `.ellenpack` 能原样灌进来。
> 复现环境：MuMu 实例 2（`127.0.0.1:16448`，Android 15 / 1080×1920 / 360×616 CSS），APK 5,282,163 B。

## 一、做了什么

| 文件 | 作用 |
|---|---|
| `app/web/src/app/core/store/db.js` | 开库/升级。库名、版本、四个 store、五个索引与旧包**逐字对齐** |
| `app/web/src/app/core/store/records.js` | head / revision 读写（追加即新 revision，不改老数据） |
| `app/web/src/app/core/store/messages.js` | 消息视图与落库（`appendMessage` / `replaceMessage` / `loadMessages`） |
| `app/web/src/app/core/store/import.js` | `.ellenpack` 解析 + head 重建 + 分批灌库 + 回读校验 |
| `app/web/src/app/core/state.js` | 每条消息一个写链；`reload()` 供导入后刷新 |
| `app/web/src/app/ui/views/settings/settings.js` | 设置页「数据与迁移 → 导入旧版资料包」 |

数据库形状（与旧包同构，所以旧数据不用变形）：

```
ellen-mobile-data-v1  version 3
├─ data-meta       keyPath 'key'
├─ data-profiles   keyPath 'id'
├─ data-heads      keyPath 'id'
│    index kind / messageTime / profileId
│    index profileKind        ['profileId','kind']
│    index profileKindThread  ['profileId','kind','threadId']
└─ data-revisions  keyPath 'revisionId'
```

## 二、`.ellenpack` 格式（从旧包 service chunk 逆出来的，逐条对上）

```
容器   = "ELLENPK1\n"(9B) + int32 大端 manifest 长度 + manifest(UTF-8) + 各文件字节
manifest v1 = { format:'ellen-companion-archive', version:1, package, files }              恰好 4 键
manifest v2 = { ...v1, version:2, selection, groupId, checksum }                          恰好 7 键
files[]     = { id, sha256, sizeBytes, mimeType }                                         恰好 4 键
package     = { content, checksum }
content     = { format:'ellen-companion-transfer', formatVersion:1, packageId,
                origin:{deviceId,platform}, exportedAt, snapshot, media }                  恰好 7 键
snapshot    = { schemaVersion:1, profiles:[], records:[] }                                恰好 3 键
records[]   每项是**一次改动（revision）**，不是 head
```

关键点三条：

1. **`snapshot.records` 里没有 head**。旧包靠 `id` 分组 + `at` 排序把历史推出来，所以导入时要重建 head — `rebuildHeads()` 干这个，`threadId` 从 `value.threadId` 取（revision 上没有单独字段）。
2. **`package` 可以是内联 JSON 对象，也可以是字符串**。内联时清单里就有全部数据，媒体字节（blob 区）按 `metadata-only` 走，不用读。所以 `EllenArchive.pickImport` 返回的 `manifestText` 就够迁移，不必 `readImport` 搬 KB 级块。
3. **`media.mode` 必须是 `metadata-only`**，`files[]` 可以为空（`files.length === 0` 合法）。

## 三、验收证据

### 1. 纯函数层（`_临时/m4-import.js`）

```
rebuild: { heads:3, revisions:4, dropped:2, a1Revs:2, a1Thread:'thread:old-1', m3Thread:null }
bad: { badManifest:'INVALID_ARCHIVE_MANIFEST', badArchive:'INVALID_ARCHIVE' }
```
同一条消息的两版被正确归到一个 head（`a1Revs:2`），缺 `revisionId` 和不是对象的记录被计进 `dropped`（2），`memory` 无 threadId 时给 `null`。


## 四、两个必须知道的坑（都踩了）

1. **profile 缓存会让导入后一片空白。** `ensureProfile()` 把 profile 缓存住了，导入清库换了一批 profile 后，还拿旧 `profileId` 去查 `profileKindThread` 索引 → 查到空。修法：`invalidateProfile()`，`importSnapshot` 结束时必须调。症状是「`verifyImport` 全绿、库里有数据，但界面一条都不显示」。
2. **导入后当前线程会指错。** 旧包把「当前线程」放在 localStorage（`ellen.mobile.thread-selection`），**不在资料包里**。不处理的话导入完打开是空的。修法：按最近一条消息所在线程推断，写回 `data-meta` 的 `current-thread`（`pickRecentThread()`）。

## 五、还没做

- 媒体文件（图片/语音）只迁元数据，实际字节还在旧的 `ellen-media-v1` 目录里，没搬。
- 导出方向没做（新包 → `.ellenpack`），等 M8 前一起做。
- 聊天历史页 `/history` 还是占位页（要按 thread 分组读 `data-heads`）。
- `emotion` 类记录（452 条在真机上）能灌进来，但没有任何东西消费它 —— 那属于 M5 的状态机。
