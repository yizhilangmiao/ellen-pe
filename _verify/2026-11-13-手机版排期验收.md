## 三、这一轮修掉的宿主兼容问题（重要，会再犯）

1. **WebView 是 Chrome 110，不支持 `color-mix()`（需 111+）**。写进去整条 CSS 声明失效（不是降级，是消失）。实测 `CSS.supports('background','color-mix(in srgb,#fff 50%,#000)') === false`。
   全仓共 46 处，已修 12 处（`welcome.css` 进度点、`call.css` 3 处、`chat.css` 3 处纯字面量、粉晕渐变加 rgba 兜底），**其余 34 处仍在**（`memory.css` 10、`model-card.css` 6、`chat.css` 剩 4、`tokens.css` 3、`zz-frame.css` 2、`settings.css` 2…），见「四」待定项。
   写法：能算的写死 rgba；要渐进的写两行（先 rgba 兜底，第二行 color-mix 覆盖）。
2. **站酷快乐体（EllenKuaiLe）的「0」字形本身就是圆角方框**，不是缺字。计时/计数类要换等宽字体：`font-family: ui-monospace, "Roboto Mono", "Droid Sans Mono", monospace`。
3. **`adb shell input tap` 吃物理像素**，页面坐标要乘 `devicePixelRatio`（竖屏实例 dpr=2.5）。稳妥做法：CDP 里 `document.querySelector(sel).click()`。
4. 盖上 App 重装后 debug socket 名会变（`webview_devtools_remote_<pid>`），每次要重新 `adb forward`。

### 7.2 导入后聊天页空白：三个根因（都已修）

| # | 根因 | 修法 | 版本 |
|---|---|---|---|
| 1 | `importSnapshot` 的「当前线程」切换条件是 `!merge || !current`，而新装首启已自动建了空线程，merge 导入时不切 → 消息全落在旧 threadId 下 | 补一条「当前线程一条消息都没有就切」 | 0.3.3 |
| 2 | `ensureProfile()` 取 `existing[0]`：库里有两份 profile（新装空壳 + 旧包），随机挑到空的 | 挑「消息最多的那份」 | 0.3.4 |
| 3 | `currentThreadId()` 只认 meta | 空线程自愈：切到消息最多那条 | 0.3.5 |

**真凶其实在第四个地方**：`app/release.ps1` 只跑 gradle，**没跑 vite build**，

### 7.5 SSH 22 不通 + 换走 HTTP 上传（已解决）

现象：`ssh root@120.27.162.122` 报 `kex_exchange_identification: Connection closed by remote host`。

排查（都不是服务器侧的问题）：

| 检查 | 结果 |
|---|---|
| `systemctl is-active sshd` / `ss -lntp` | active，22 监听 pid 940 |
| iptables | `-P INPUT ACCEPT`，无 22 拦截规则 |
| fail2ban | 没装 |
| SWAS 防火墙（`ListFirewallRules`，7 条） | 22 对 `0.0.0.0/0` **accept** |
| 服务器 auth 日志 | 只有 `177.126.132.44` 的爆破记录，**没有本机出口 IP 的任何连接** |

结论：链路中间被掐，不在服务器。→ 换通道，不折腾 SSH。

**新通道**：nginx 自带 `--with-http_dav_module`，8080 通 → 临时开一个 PUT 口传包，传完立刻撤掉。
已封装成脚本：

```powershell
pwsh -File _tools/upload_release_http.ps1 -Apk "_build\release\ellen-0.3.8-arm64-v8a.apk" -Version 0.3.8 -VersionCode 9 -Notes "一句话说明"
```

它做四件事：云助手开临时 `location /__up/`（`dav_methods PUT` + `client_max_body_size 200m`）→ `curl -T` 上传 →
服务器改名 + 重写 `latest.json` + 恢复原 nginx 配置 → 线上自检（manifest 200、apk Range 206）。

**踩过的坑**：上传文件名不能以 `.apk` 结尾 —— `location ~* \.apk$` 是正则位置，优先级高于前缀位置，
会把请求从 `/__up/` 抢走，吃 http 层默认 1MB 限制，直接 `413 Request Entity Too Large`。加 `.part` 后缀即可。

2026-11-13 13:25 用这条通道把 **0.3.8（versionCode 9）** 推上线：
`http://120.27.162.122:8080/latest.json` → 0.3.8，`sha256 8b05036c0be2cf52da0a37fb3014293346a9db0373b0573498bcce9154040619`，
与服务端 `sha256sum` 一致、`curl -r 0-1023` 返回 206。
