# M15 · 随机语音条（点开才合成）

> 状态：已验收（10 项实测过、竖屏图在）2026-11-11 16:05　写于 2026-11-11
> 验收人：web-chat　改动文件：`app/web/src/app/ui/views/chat/chat.js`（`clipBar()`）、`chat.css`（末尾追加）
> 范围外：`core/speech.js` / `main.js` / `core/state.js` 一行没动

## 1. 为什么要做

文字聊久了会像在跟「输入框」说话。真人聊天里，语音条是低成本、高在场的动作：她懒得打字，丢一条 3 秒的语音过来。

但语音合成按次计费，**每条都合成既费钱又吵**。所以产品定的是「偶尔一条、点开才合成」：

- 生的时机：一轮回复结束后按概率决定（不是每条都有）
- 花的时机：用户真的点下去才调 minimax
- 听到的时机：合成成功立刻播放，不落盘、不预取

## 2. 概率与开关

| 项 | 值 | 位置 |
| --- | --- | --- |
| 概率 | 1/7（`CLIP_ODDS = 7`，`Math.floor(Math.random() * 7) === 0`） | `core/speech.js` `maybeClip()` |
| 开关 | `prefs.clip`，默认 `false` | localStorage `ellen.voice.v1`（`DEFAULTS` 同文件） |
| UI 入口 | 设置 → 声音 → **第二个** `.el-settings-toggle-row` | `ui/views/settings/settings.js` |
| 落库字段 | `voice: true` 打在最后一条 assistant 消息上 | `main.js` `maybeAttachClip()` → `appState.updateMessage()` |
| 渲染条件 | `msg.voice && role !== 'user' && !pending && !failed && text 非空` | `chat.js` `renderMessage()` |

只有「开关打开 + 概率命中」同时成立才会有条；关掉后已存在的条照旧可点（数据里的 `voice` 不清）。

## 3. 合成与缓存

条本身**不含音频**：`clipBar()` 只画圆点 + 12 根 `:nth-child` 波浪 + 时长（`字符数 / 5`，最少 2″）。

点第一次才走链路：

```
click → synthesizeUrl(msg.text)          // core/speech.js
      → readKey()  // EllenSecureConfig.read({ scope: 'tts' })，JSON 形态会摊平成裸 key
      → EllenSpeech.synthesize({ text, apiKey, endpoint, model, voiceId, speed })
      → base64 → Blob → URL.createObjectURL
      → clipCache.set(msg.id, url)       // 同一条不再花第二次钱
      → new Audio(url).play()
```

- 再点一次：`audio && !audio.paused` → `pause()` + 摘 `is-playing`，**不动 cache**
- 第三次点：走 cache 命中分支，直接新建 `<audio>` 重放，`synthesize` 调用数**不增加**（实测 1）
- 已知欠账（**2026-11-11 已修**）：原来 blob URL 从不 `revoke`，聊得越久常驻越多（1/7 概率，700 句就是 100 个）。现在视图 `destroy()`（router 切走页面时自动调）里逐个 `URL.revokeObjectURL()` 再 `clipCache.clear()`；切走再回来点是**重新合成**，不再复用旧 URL

## 4. 失败与重试（这一节是重点）

### 病根：重试是真的，"没反应"也是真的

改之前用户反馈「点了一下没声音，再点就没反应了」。查下来**不是点不动**——每次点击都完整走了一遍合成，`synthesize` 调用数 1 → 2 → 3，重试一直在跑。

坏的是**反馈**：

| 现象 | 原因（`clipBar()` 旧代码） |
| --- | --- |
| 看不出在加载 | `is-loading` 加上去、失败立刻摘掉；本地 `NO_API_KEY` 800 ms 内返回，透明度那点变化肉眼抓不到 |
| 看不出又失败了 | 失败分支只有 `node.classList.add('is-clip-failed')`，**全文件没有一处 `remove('is-clip-failed')`**，第二次的红和第一次一模一样 |
| 不知道为什么失败 | 条这条链路没有文案；`flash()` 是朗读按钮（`.el-msg-speak`）在用，条没接 |
| 配好 key 也还是红的 | 成功分支同样不摘 `is-clip-failed`，红边只能靠整页重绘消失 |

一句话：**「功能对、反馈错」的 bug，验收时最容易被写成 PASS**——点下去有网络请求、不报错、不崩，看起来都正常。

### 改法（`chat.js` `clipBar()`，2026-11-11）

1. 点下去第一件事 `clearFail()`：摘 `is-clip-failed` + 清空并隐藏文案 → 加载态一定看得见
2. catch 里多留 `code` 字段（原来只留 message，分不出 `NO_API_KEY`）
3. 失败文案挂在气泡里（`span.el-msg-clip-note`，`node.insertBefore(note, bar)`）：
   - `NO_API_KEY` → 「还没配朗读的 key，去设置 → 声音里填一下」
   - 其余（`TTS_NETWORK` / `TTS_FAILED` / 未知）→ 「这条念不出来，等下再点一次」
4. CSS 追加 `.el-msg-clip-note` + `[hidden]{display:none}`（类里写了 `display:block` 会盖掉 `hidden`，必须兜）
5. **不碰 `main.js` / `speech.js`**：失败可重试的逻辑本来就是对的，只补反馈

## 6.5 两个坑（本轮现学）

1. **`.el-msg` 不是 flex 是 grid**（zzz 皮肤：`grid-template-columns: 32u minmax(0,1fr)`，头像 `::before` 占列 1）。默认皮肤才是 `column flex`。新加的子元素在 grid 里被 `align-items:start` + 自动放置压成「一个字一行、宽 27px」——元素在、不报错、`textContent` 也非空，**只有肉眼看图或量盒子才看得出来**。
   - 判据补一条：**凡是新增可见元素，必须量 `getBoundingClientRect().width`**，不能只看文案非空。
   - 修法：`.el-msg-clip-note { grid-column: 2; justify-self: stretch; align-self: stretch; }`（flex 皮肤下只有 `align-self` 生效，两套皮肤都能撑满）。
2. **「先破坏再验证」的脚本，破坏前必须备份、收尾无条件回写**。本轮两次把 vault `tts` 留在空状态：脚本中途 `return`，`read → remove` 之后没走到 `write`。改成 `window.__bak` 备份 + 独立 `restore.js` 兜底。
