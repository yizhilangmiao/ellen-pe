# M7 · 应用内更新（EllenUpdates）

> 2026-11-10 · 会话 dsh:e54e06 · 新包 `0.3.0-m6`（versionCode 1）

## 一、为什么做

旧包的更新链是「查 COS 上的 `latest.json` → 下载 apk → 校验 sha256 → 拉起系统安装」，逻辑本身是好的，
问题只有一个：**地址写死在别人的桶里**（`aapt2 dump strings` 取到 resource 里的两条）：

```
https://ellen-updates-1410769069.cos.ap-guangzhou.myqcloud.com/updates/android/development/latest.json
https://ellen-updates-1410769069.cos.ap-guangzhou.myqcloud.com/updates/android/stable/closed.json
```

那是旧作者的腾讯云桶。新包照抄这套机制，但把地址变成**可配**：默认空字符串 = 不联网、不报错，
设置页的「关于与更新」里（调试包才显示输入框）填自己的地址。

## 二、native 契约（`EllenUpdatesPlugin.kt`）

旧包 5 个 `@PluginMethod`，新壳保持 5 个 + 新增 1 个 `configure`：

| 方法 | options | 行为 | 错误码 |
|---|---|---|---|
| `state` | — | 直接回当前状态 | — |
| `check` | — | GET 清单 → 校验 → 与 versionCode 比对 | `UPDATE_FAILED` |
| `download` | — | Range 续传 + sha256 校验 | `UPDATE_BUSY` / `UPDATE_FAILED` |
| `install` | — | FileProvider + `ACTION_VIEW` 拉起系统安装页 | `INSTALL_UNAVAILABLE` |
| `cancel` | — | 置标志位，正在读的流下一次循环就停 | — |
| `configure` | `manifest` | 存清单地址；空 = 关掉更新 | — |

事件 `updateState`，state JSON：

```json
{ "supported": true, "phase": "idle|checking|current|available|downloading|ready|
   verifying|installing|permission|unpublished|cancelled|error",
  "sequence": 7, "message": "发现新版，可查看更新内容并下载。",
  "received": 11492782, "total": 100123802, "canInstall": true, "lastError": "",
  "current": { "version": "0.3.0-m6", "versionCode": 1 },
  "latest": { "version": "0.3.0-m7", "versionCode": 2, "notes": "…", "publishedAt": "…",
              "apk": { "sha256": "<64hex>", "url": "https://…/app.apk", "sizeBytes": 100123802 } } }
```

清单格式（照旧包）：

```json
{ "schemaVersion": 1, "platform": "android", "packageName": "cn.ellen.companion2",
  "channel": "development", "version": "0.3.0-m7", "versionCode": 2,
  "publishedAt": "2026-11-10T06:04:14Z", "minSdkVersion": 24, "notes": "…",
  "apk": { "sha256": "5174ea…", "url": "https://…/app.apk", "sizeBytes": 100123802 } }
```

校验口径：`schemaVersion==1`、`platform==android`、`packageName==context.packageName`、`versionCode>0`、
`sha256` 必须 `^[a-f0-9]{64}$`、`url` 非空且 **https**、`minSdkVersion > Build.VERSION.SDK_INT` 直接拒。

## 三、几处刻意的取舍

1. **不做「下载完自动跳到安装」**：系统安装页要用户自己点确认，代跳只会让人以为软件在偷偷装东西。
   `install` 只负责把 intent 送出去，装完不装完由系统决定。
2. **先查权限再发 intent**：`canRequestPackageInstalls()` 为假时 `phase=permission` 并打开
   `ACTION_MANAGE_UNKNOWN_APP_SOURCES`，回来自动能再点一次「去安装」。
3. **换版本清缓存**：`check` 一旦发现 `versionCode` 变了就删掉 `cache/update.apk` 与 `update.part`，
   否则会拿上一版的半截包去校验，报「校验失败」但看不出为什么。
4. **`abort` 不留垃圾**：`cancel` 不删 `update.part`（要续传）；校验失败才删。
5. **FileProvider 单独一条 authority**：`${applicationId}.updates` → 只暴露 `cacheDir`（`res/xml/updates_paths.xml`），
   与聊天附件那条 `${applicationId}.fileprovider` 分开，权限范围互不影响。

## 五、坑

1. **明文 http 被系统拦掉**（Android 9+ 默认）：报的是一句泛化的「更新未完成，请检查网络后重试。」，
   第一版没带异常细节，白查了十分钟。现在兜底文案会带 `异常类名: message` 前 160 字。
   同时加了 `res/xml/network_security_config.xml` 只对本机回环（`127.0.0.1` / `localhost` / `10.0.2.2`）放行明文，
   公网仍然强制 https。
2. **这个模块没开 `buildConfig` 生成**：写 `BuildConfig.DEBUG` 会 `Unresolved reference`，
   要用 `context.applicationInfo.flags and ApplicationInfo.FLAG_DEBUGGABLE`。
3. **`cancel()` 返回的 phase 还是 downloading**：它在置标志位后立刻回快照，真正停下要等读流循环下一轮。
   界面靠 `updateState` 事件刷新，别拿 `cancel()` 的返回值当最终状态。
4. **模拟器自带安装器会崩**（`MuMuInstallStaging`）：验证只能到「intent 已送达安装器」这一步。
5. `adb reverse` 是会话级的，模拟器重启就没了，测完记得 `adb reverse --remove-all`。

## 六、还没做

- 正式发布通道：现在没有自己的桶/域名，`configure` 空着就是「暂未发布更新」。要发版得先定一个 https 静态站。
- 自动检查频率：现在只有用户点「检查更新」才查；旧包是启动时顺手查一次（可加，但会多一次联网）。
- 签名校验：旧包会比对「安装包签名与原应用一致」，我们目前只校验 sha256（清单在我们手里，够用；
  等有了第三方分发再补 `PackageManager.getPackageArchiveInfo` + 签名比对）。
- 静默失败兜底：`install` 里 `startActivity` 抛异常时只改状态，不弹提示（靠状态行看）。

## 七、发版脚本（`app\release.ps1`，2026-11-10 加）

应用内更新只认 `latest.json`（字段见 §二），以前靠手拼，sha256 手抄必错。现在一条命令出全套：

```powershell
pwsh -File E:\ailian\艾莲手机版\创作版\app\release.ps1 -Notes "这一版改了什么"
pwsh -File ...\app\release.ps1 -SkipBuild          # 只重算 hash / 重写清单
pwsh -File ...\app\release.ps1 -Abi arm64-v8a      # 只出真机那个包
pwsh -File ...\app\release.ps1 -BaseUrl https://你的静态站/ellen  # url 拼成绝对地址
```

产出目录 `创作版\_build\release\`：`ellen-<version>-<abi>.apk` ×2、`latest.json`、`index.json`。
脚本自己会核三件事：`versionCode` 从 `build.gradle.kts` 读（不写第二份）、`sha256` 写完读回来复算一次、包体大小与清单一致。

**两条坑**（都已写进脚本注释）：
1. 文件名必须 ASCII —— 中文名进了 `url` 会被百分号编码，客户端拼地址容易 404。所以脚本产出 `ellen-0.3.0-m7-arm64-v8a.apk`，不是「艾莲-…apk」。
2. `latest.json` 必须 UTF-8 **无 BOM** —— 带 BOM 时 Java 侧解析炸在第一字节（`WriteAllText` + `UTF8Encoding($false)`）。

**还是 debug 签名**：发给别人之前要先做 release keystore；keystore 与口令不进 git（`.gitignore` 已排除 `*.apk`，但 keystore 要自己加）。
**通道仍留空**（老大 2026-11-10）：脚本只产本地文件，不上传、不写死托管地址。
