# M7 · 反馈通道（D12）：把信从别人的服务器手里拿回来

日期：2026-11-09 · APK `0.3.0-m6` · 98,624,563 B · 15 个自有插件
设备：MuMu 实例 2（`127.0.0.1:16448`，Android 15 x86_64，无邮件 App）

## 一、为什么要做（硬点 D12）

旧包的反馈链不在我们手上。`EllenFeedbackHttpPlugin` 里两个字符串常量是写死的：

```
ENDPOINT = "https://formsubmit.co/ajax/1520208183@qq.com"
SOURCE   = "https://formsubmit.co/el/xutine"
LIMIT    = 0x8000
```

也就是说：

1. **信先寄到一个第三方**（formsubmit.co），再由它转发到那个 QQ 邮箱。转发方随时能停、能看、能改；
2. 旧包**没有网络时整条链直接断**，用户连「先把话写下来」都做不到；
3. 反馈内容里带什么、留多久，全看对方的政策，我们这边一点记录都没有。

新壳不接这个端点，改成「本机拼信 → 交给系统邮件 App」：不经过任何第三方服务器，离线也能先把信写下来（写下来就存在输入框里，切页不丢）。

## 二、native：`EllenFeedback`（3 个方法）

`app\app\src\main\java\cn\ellen\companion2\plugin\EllenFeedbackPlugin.kt`

| 方法 | 入参 | 返回 |
|---|---|---|
| `info()` | — | `{ to, subject, hasMailApp, version }` |
| `send({subject, body})` | 两个字符串（subject 截 120、body 截 20000） | `{ ok:true, via:'mail'\|'clipboard' }` |
| `copy({text})` | 文本 | `{ copied:true }` |

`send` 的判定顺序：

1. `Intent(ACTION_SENDTO, mailto:<DEFAULT_TO>?subject=…&body=…)` 能不能被解析（`resolveActivity`）；
2. 能 → `activity.startActivity(intent)`，返回 `via:'mail'`（信进邮件草稿，**用户自己点发送**，不是我们偷偷发）；
3. 不能 → 整封信写进剪贴板，返回 `via:'clipboard'`；
4. 拉起时抛异常（邮件 App 被冻、系统限制）→ 同样退剪贴板，**不把信丢掉**；
5. 连剪贴板都写不进 → `reject("这台机器没有邮件 App，剪贴板也写不进去。", "FEEDBACK_UNAVAILABLE")`。

两条错误码：

| code | 文案 | 什么时候 |
|---|---|---|
| `FEEDBACK_EMPTY` | 信里还没有内容。 | body 去掉空白后是空 |
| `FEEDBACK_UNAVAILABLE` | 这台机器没有邮件 App，剪贴板也写不进去。 | 两条路都断 |
| `FEEDBACK_FAILED` | 没打开邮件 App：<异常类名> | 前面两条都命中失败 |

**为什么不加 `INTERNET` 权限自己 POST**：那就又需要一个「我们的服务器」，现在没有；而反馈本来就是一对一的手工收信，邮件是最省事的通道。等以后有接口了再加一个 `sendRemote` 分支即可。

`MainActivity.kt` 注册在 `EllenLocalSpeechPlugin` 之后（仍全部在 `super.onCreate` 之前）→ 自有插件 **15 个**。

## 三、web：`core\feedback.js`

- `KINDS = ['chat','app','words']`（她说的话 / 功能问题 / 想说的话）。
- `info()` 结果缓存一份；native 拿不到时（浏览器里跑 `probe.html`）回兜底 `FALLBACK_TO = '1520208183@qq.com'`、`hasMailApp:false`。
- `compose({kind, text})` 拼信，正文后面自动补四行环境信息：

  ```
  <用户写的正文>

  ——
  版本：0.3.0-m6
  分类：功能问题
  Android：15
  时间：2026/11/9 23:07:12
  ```

  机型只从 `navigator.userAgent` 里抠 Android 版本，不申请任何权限去读设备标识 —— 反馈是为了定位问题，不是为了认人。

- `send({kind, text})` → `{ ok, via, letter }`；空文本抛 `FEEDBACK_EMPTY`（带 `err.code`，视图据此换文案）。
- `copy(text)` 单独一条，给「我只想粘到别处」的人。

## 四、视图：`ui\views\feedback\feedback.js`（全屏页）

版式跟手记详情、聊天历史同一套（`el-eyebrow` → `h1.el-page-title` → `p.el-page-subtitle` → 内容 → 主按钮）：

```
TELL ME
想说点什么
你写的会直接到开发者手里，不经过别人的服务器。
这是关于    [她说的话] [功能问题] [想说的话]

                                                          33 字
[寄出去] [只复制]
这台机器没有邮件 App，会把整封信复制到剪贴板。
```

- 入口两个：相处页的圆形信箱按钮（旧包那份「写信给她」草稿，之前没接线）、设置页最后一张卡「写信给她 · 直达开发者 → 写一封信」。
- 底部那行 `note` 会先说明**这封信会走哪条路**（`routeMail` / `routeCopy`），发完再换成结果（`sentMail` / `sentClipboard`）。**不假装寄出去了** —— 模拟器上没有邮件 App，要是只说「已发送」，用户会以为信飞走了。
- 走剪贴板时**输入框里的字不清空**（他可能想改一句再发一次）；走邮件 App 才清空。
- 字数提示 `{n} 字`，上限 4000（`MAX_BODY`）。

## 六、坑

1. **借用别的页面的样式类会静默失效**：第一版分段按钮直接用了设置页的 `el-settings-segment`，而它的选中态依赖 `--el-current-primary`，这个变量是 `.el-settings-context` 派生的 —— 反馈页没有那个祖先，于是三个按钮全一样、看不出选了哪个（截图里就是这么拍到的）。改成自己的类名 `el-feedback-kind` + 用全局 `--el-primary` / `--el-primary-ink`，`getComputedStyle` 一验就知道对不对。
2. **`mailto:` 的 `?` 必须编码**：直接用字符串拼 `mailto:addr?subject=中文` 在某些邮件 App 里会把中文参数吃掉，改用 `Uri.Builder().scheme("mailto").opaquePart(to).appendQueryParameter(...)`。
3. **不要拿「挡住了 Intent」当成功**：`resolveActivity` 返回 null 时 `startActivity` 会抛 `ActivityNotFoundException`，必须接住并退剪贴板，否则用户点一下就看到崩溃。
4. **`setPrimaryClip` 在 Android 13+ 会给用户一个系统提示**（「已复制」气泡），这不是我们的 toast，别重复提示。
5. **验 APK 内容不能看大小**：这次 98,624,565 → 98,624,563 B（差 2 字节）就换了样式，必须用 python `zipfile` 读 `classes*.dex` 里的 `EllenFeedback` / `FEEDBACK_EMPTY` / `mailto`，再读 `assets/public/assets/*.js` 里的 `el-feedback-page`。
