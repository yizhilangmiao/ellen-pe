验收日期：2026-11-04 · 包 `cn.ellen.companion2` 0.3.0-m5 · MuMu 实例 2（Android 15，360×616 CSS）

## 一、这一页原来是什么

M0–M4 阶段「相处」是 `ui/views/placeholder.js` 的占位页，三行文字，没有数据。

## 三、数据层（`core/companion.js`）

```
RELATIONSHIPS  恋人 / 亲近 / 朋友 / 刚认识（默认 lover）
daysTogether() 最早一条消息 → 天数；一条消息都没有才退回 meta first-seen
currentMood()  listLatest('emotion',{limit:1})，没有就 null → 页面显示「待了解」
composeMood()  一次模型调用同时产出 {mood, note}
maybeRecordMood()  6 小时内只记一次（MOOD_GAP_MS）
setRelationship(id)  写 meta
```

`emotion` 记录的 value：`{mood, note, at, sourceIds[]}`。`sourceIds` 留最后 6 条消息的 headId，
以后「她为什么这么想」能追回去。

**为什么 mood 与 note 一次问出来**：便签是「此刻想说的话」，心情是「此刻什么状态」，
分两次问会自相矛盾（旧包也是绑在一起的）。

**为什么 6 小时才问一次**：聊十句就问十次模型，钱和延迟都不值；相处页的心情本来就该是慢变量。

`values.mood` 限 8 字、`note` 限 60 字，模型话多时截断，不撑破版式。

## 五、五个坑

1. **`portrait-v1` 是四格贴纸**，必须裁一格。直接 `object-fit:cover` 会显示四张脸。
2. **`display:inline-block` 会盖掉 `[hidden]`**。心情有了之后想把这行解释藏掉，
   光写 `hidden` 不生效，得补 `.el-companion-mood-note[hidden]{display:none}`。
3. **flex column 会压扁最后一个块**。相处页内容比一屏高，`flex-shrink` 默认 1 把点线块
   从 144u 压到 39u，`overflow:hidden` 再把「每一天，都算数。」和天数胶囊裁掉。
   修法：`.el-companion-page > * { flex: 0 0 auto }`，让页面自己滚。
4. **便签别写两遍**。心情那块与便签卡都显示 `value.note` 时，屏幕上同一句话出现两次。
   现在有 note 就把心情块那行藏掉，只在「还没心情」时用它解释为什么显示「待了解」。
5. **`pwsh` 里没有 bash heredoc**。`python - <<'PY'` 直接语法错误，多行 python 要先写文件再 `& python file.py`。
   另外 `-replace` 后面跟多个拼接参数会报「只能跟两个元素」，改用 python 批量替换更稳。

## 六、还没做

- **信箱按钮没接线**：旧包这里是「写信给她」（本地邮件草稿样式），归 M7 的 D12 反馈通道一起做。
- **「我们之间」下面那句感受**还是静态文案「相处里的感受，还没有留下记录。」——
  旧包这里读的是 `ellen-close` 那套亲密度记录，新壳要等 `relationship` 记录化（现在只有 meta 一个等级）。
- 立绘只有一张（平静脸）。旧包四格里另外三格（害羞 / 托腮 / 笑）可以做「心情 → 表情」映射，
  等心情词的取值稳定下来再挂。
- 竖屏锁定：manifest 是 `screenOrientation="portrait"`，横屏截图与竖屏一致（转了也没变），
  与旧包一致。以后要支持横屏得先改 manifest 再补 `layout/landscape.*`。
