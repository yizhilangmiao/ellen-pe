# M5 · 手记（她写给自己看的那一篇）

> 老大第一版必含清单里有「手记整理」。旧包把这件事塞在 web 层一个超时只有 30 s 的 IndexedDB 事务里
> （老 bug ①），事务被掐断就整篇丢失。新壳重写，字段名照旧包，落库改成短事务。

## 一、判据：什么时候写

`app/web/src/app/core/journal.js` 的 `dueFor()`：

| 条件 | 值 | 理由 |
|---|---|---|
| `MIN_MESSAGES` | 3 | 少于三条不值得写一篇 |
| `MIN_GAP_MS` | 4 小时 | 同一天补写太密会变成流水账 |
| `LOOKBACK` | 40 条 | 素材上限，别把整个上下文喂进去 |

判据不是「到点就写」，而是「**距离上一条手记（或今天零点）之后有没有新对话**」——
只看消息的 `createdAt` 是否晚于上次写入。所以：早上聊两句 → 晚上再聊两句，会写成一篇；
一天没说话，就不写。

## 二、怎么写

`compose()` 走 `core/chat/oneshot.js`（非流式一次性提问）：

- system 明确要求「写给自己看的日记，不要总结成『今天我们聊了……』，挑一两个记住的瞬间」；
- 输出格式锁成 `{"title","diary","thoughts"}` 三键 JSON；
- `max_tokens: 900`，`thinking: { type: 'disabled' }`（老 bug ⑩：开着思考会拖到超时还没内容）；
- 模型没照格式写时**不丢内容**：整段当 `diary`，标题取首行前 12 字（`looseJson` 先试围栏、再试首尾大括号）。

## 三、怎么落库（老 bug ① 的解法）

- 一天一篇：`day`（`2026-11-04`，设备本地日）+ `timeZone`（`Asia/Shanghai`）是主键语义。
- 今天已有 → `reviseRecord(headId, value)` 追加一条 revision；没有 → `appendRecord({kind:'journal'})`。
- **模型调用与落库彻底分开**：先把整篇在内存里攒完，再一次短事务写下去。
  旧包是把「等模型 + 写库」放在同一个 web 事务里，30 s 一到整篇作废。
- 手记是全局的，`threadId` 传 `null`（不挂在某个会话线程下，换线程也看得到）。

`value` 15 个字段全按旧包命名，旧资料包导进来能直接读：

```
namespace, version, scope, day, timeZone, title, diary, thoughts,
sourceIds[], processedIds[], understanding{body,sourceIds,processedIds,updatedAt},
retained, createdAt, updatedAt, editedBy
```

## 四、触发点

| 时机 | 位置 |
|---|---|
| 每轮聊天结束后 | `main.js` 的 `onSend`（不 await 到界面路径，失败只 console.warn） |
| App 回到前台 | `document.addEventListener('visibilitychange')` |
| 手动 | `window.__ellen.journal.{due,today,compose,force}` |

并发保护：模块级 `running` 标志，正在写就直接返回 `{skipped:'running'}`，不会同一天连开两篇。

## 五、实测（MuMu 实例 2 / Android 15 / 12:22–12:31）

```
journal.due()      → {due:true, day:"2026-11-04", count:4}
journal.force()    → 2470 ms，headId=journal:1eddbf33…，title「豆豆和那顿饭」，revised=false
journal.force() 再跑 → revised=true，同一个 headId，title 变成「问了四遍的事」
journal.today()    → day=2026-11-04, timeZone=Asia/Shanghai, valueKeys 15 个齐全
journal.due() 之后 → {due:false, reason:"tooSoon"}   ← 4 小时间隔生效
记忆页「我们的回忆」→ 两张卡：2026-11-04「问了四遍的事」/ 2026-11-01「安静的一天」（旧包导入的）
```

`force()` 只用 2.5 秒（thinking 关了 + 非流式），比旧包那条 30 s 悬崖安全得多。
