# M3 · web 聊天壳验收（v0.3.0-m3）

日期：2026-11-03　设备：MuMu 实例 1（Android 15 / 1080×2400 / 432×936 CSS）
包名：`cn.ellen.companion2`　APK：`app\app\build\outputs\apk\debug\app-debug.apk`（5,179,454 B）

## 一、这一版做到了什么

旧包那 7 MB 无源码的 web 产物被整段换掉，换成我们自己的 Vite 工程；**聊天页能从输入框发出一句话、
拿到服务端返回（含流式读块与错误体），并在界面上正确收尾**。原生侧仍是 M2 已验收的 13 个插件，没动。

界面骨架（顶栏 / 底栏 / 聊天页 / 设置页）与旧包同构：根容器实测 **432×936 CSS**，与旧包逐像素同尺寸；
两套主题（`dark` / `light`）都用旧包实测令牌值。

## 四、关键实现细节（后续要接的东西都依赖这些）

1. **端点不可配**：原生 `EllenModelHttp` 把 host/path 写死为
   `https://ark.cn-beijing.volces.com/api/plan/v3/chat/completions`，改域名会被拒成
   `INVALID_MODEL_HTTP_REQUEST`。所以设置页只让填 key 与模型名，不提供"改地址"（假开关不做）。
2. **流式读法**：`open` 拿状态 → `read(requestId, sequence)` 从 **1** 开始递增到 `done` →
   每块是 base64，必须用 `TextDecoder({stream:true})` 跨块解码（中文会被切断）。
   SSE 按 `\n\n` 切事件，只认 `data:` 行，跳过 `[DONE]`。
3. **派发器语义**（`bridge.js`）：`signal` 中断时用同一 `requestId` 调 `cancelMethod`；
   `cleanup:true` 的失败路径必须再执行一次清理，清理又失败时合成 `AggregateError`（不吞原始错误）。
4. **`[hidden]` 要自己压住**：组件的 `display:inline-flex` 会盖掉 `hidden` 属性，
   `base.css` 里有一条 `[hidden]{display:none!important}`。踩过一次（停止键一直显示）。
5. **`--u` 标尺**：`clamp(0.84px, 0.2315vmin, 1.16px)`，旧包 `Npx` 一律写成 `calc(N * var(--u))`，
   432 宽屏时恰为 1px。这样改版换基准屏只改一个数。

## 五、还没做（下一批）

- **真 key 的成功分支**：需要老大在设置页填一次自己的 key + 模型名（key 只落在本机 KeyStore，
  不进备份、不上报），填完发一条即可闭环。
- **工具栏与底栏图标**：现在用 `◎◐◔♡⚙` 这类符号占位，旧包是线框 SVG，要照抄一遍。
- 聊天历史页、状态与提醒页、更换背景页（现在是占位）。
- 消息落地（M4 IndexedDB 事件溯源）、回复节奏、记忆检索、手记、主动消息。
