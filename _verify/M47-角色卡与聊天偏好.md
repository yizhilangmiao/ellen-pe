# M4.7 角色卡 + 聊天偏好 + 手记整理（设置页最后三个「即将可用」）

日期：2026-11-09 · APK `0.3.0-m6` · 98,618,014 B（含 sherpa-onnx 与离线识别模型）
设备：MuMu 实例 2（`127.0.0.1:16448`，Android 15 x86_64）

## 一、为什么要做

设置页底部还剩四个「即将可用」的假卡片（`settings.js` 里 `const placeholders = [...]`）。老大 m04690 定「语音先不做」之后，剩下三项正好是第一版必含项里缺的最后一块：

| 卡片 | 对应必含项 | 没有它的后果 |
|---|---|---|
| 角色卡 | 聊天本身 | **聊天根本没有 system prompt** —— `createChatSession({ state })` 从头到尾没传过人设，艾莲说话全凭模型默认人格 |
| 聊天偏好 | 聊天 + 回复节奏 | 上下文条数、记忆召回、思考模式全写死在代码里，用户改不了 |
| 手记整理 | 手记整理 | 手记只能靠「聊完自动触发」，没有开关也没有手动补写 |

第四个「语音模型」按老大要求留空，标「后面补上」，不做假开关。

## 二、角色卡（`app\web\src\app\core\persona.js`）

存 localStorage `ellen.persona.v1`（**不进 vault**：这里没有密钥，只有称呼和脾气；走 vault 会多一次原生往返，导入导出时还会被当成敏感数据）。

```js
DEFAULT_PERSONA = { name:'艾莲', callMe:'', tone:'soft', length:'short', note:'' }
TONES   = ['soft','quiet','teasing','clingy','cool']
LENGTHS = ['short','normal','long']
readPersona() / writePersona(patch) / resetPersona() / describePersona()
buildSystemPrompt({ persona, relationship, now })
```

`buildSystemPrompt` 拼出来的前五行（实测原文）：

```
你是艾莲。你和豆豆在一起，是恋人关系。
话不多，安静，偶尔一两句，不解释自己为什么少话。
一次说两三句，够把意思说清楚就行。
说话像真人：不用敬语，不说「作为一个 AI」，不叫对方「用户」。
不要复述他说过的话，不要总结这段对话，不要问他「还有什么想聊的」。
```

三条写死的规则都有来由：

- **不复述、不总结**：模型爱写「你说你在加班，我理解你…」，读着像客服。
- **不用列表和标题**：气泡里出现 `- ` 和 `##` 很出戏。
- **强调只用 `**粗体**`**：`richtext.js` 把它渲染成粉色（`EllenKuaiLe` 只有 400 一个字重，加粗会拖灰影）。

另外按时间加一句：23–6 点「说话轻一点，劝他早点睡但别唠叨」；6–9 点「问一句昨晚睡得怎么样」。

**关系不另存一份**：角色卡的关系分段直接读写 `companion.js` 的 meta（`relationship()` / `setRelationship()`），所以相处页那枚「恋人」徽章和设置页是同一份数据。

## 三、会话侧接线（`core\chat\session.js`）

```js
createChatSession({ state, systemPrompt = '', getSystemPrompt = null })
```

`getSystemPrompt` 是**函数**而不是字符串：人设能在设置页改，改完下一条消息就该生效；重开会话会把 `inflight` 里正在流的回复丢掉。

`send()` 里每轮现取：

```js
const prefs = readChatPrefs();
const history = state.getMessages()...slice(-prefs.history);
let sys = systemPrompt;
if (typeof getSystemPrompt === 'function') sys = await getSystemPrompt();
...
if (prefs.recall) recalled = await recall(trimmed, { limit: prefs.recallLimit });
const think = prefs.thinking !== 'default' ? prefs.thinking : cfg.thinking || 'default';
```

`main.js`：

```js
async function currentSystemPrompt() {
  const [persona, relation] = await Promise.all([readPersona(), relationship()]);
  return buildSystemPrompt({ persona, relationship: relation });
}
const session = createChatSession({ state: appState, getSystemPrompt: currentSystemPrompt });
```

## 四、聊天偏好（`app\web\src\app\core\chatprefs.js`）

localStorage `ellen.chat.v1`，跟 model config 分开存（换平台不该把这些一起重置）。

| 键 | 默认 | 说明 |
|---|---|---|
| `recall` | `true` | 关掉后 system 段里不再出现「她记得的事」 |
| `recallLimit` | `6` | 3 / 6 / 9 / 12 条。老 bug ③ 是「永远同样 7 条」，新壳按条数给死上限 + 打分排序 |
| `history` | `20` | 10 / 20 / 30 / 50 条 |
| `thinking` | `'default'` | `default` 跟随模型；`disabled` 关掉（省时间省钱，手记/记忆那两处本来就 `disabled`） |

记忆关掉时，条数那一栏加 `.is-muted`（`opacity .45` + `pointer-events:none`）——**不藏起来**，藏了他会以为设置丢了。

## 五、手记整理（`core\journal.js`）

`ellen.journal.v1`：

```js
DEFAULT_JOURNAL_PREFS = { auto:true, minMessages:3, minGapHours:4 }
readJournalPrefs() / writeJournalPrefs(patch)
```

- `maybeCompose()` 开头加 `if (!readJournalPrefs().auto) return { skipped:'off' }` —— 关掉后所有调用点（聊完 / 回前台 / 设置按钮）自动都停，不用各改一遍。
- `dueFor()` 用偏好里的 `minMessages` / `minGapHours` 取代原来的常量，所以「至少聊几条」「最短间隔」改完立刻生效。
- 设置页「让她现在写一篇」直接调 `maybeCompose`，把 `skipped` 翻成人话：

| skipped | 文案 |
|---|---|
| `tooFew` | 这几句还太少，再聊几句。 |
| `tooSoon` | 刚写过一篇，过几个小时再写。 |
| `off` | 手记整理是关着的，先打开。 |
| `running` | 正在写，等这篇写完。 |

## 七、坑

1. **同名变量把构建撞死**：新加的占位卡也叫 `voiceCard`，与声音卡里的 `const voiceCard` 重复 → `Identifier "voiceCard" has already been declared`，vite 直接失败。改成 `ttsCard`。
2. **探针写库后 DOM 不会自己重画**：`app.persona.write()` 只动 localStorage，页面上的输入框还是旧值。要看到真值必须重启或先触发一次 `paintPersona()`。第一次截图拍到的是测试值（豆豆 / 安静 / 正常），确认方法：重启后读 `cardStatus`。
3. **`.el-settings-context` 会短暂为 null**：刚切页时 `document.querySelector` 拿不到（视图是挂载时创建的），探针里要 `await 800ms` 再取；否则报 `Cannot read properties of null (reading 'querySelectorAll')`。
4. **分段按钮是一次性画的**：「恢复默认」把 prefs 改回去之后，按钮的 `is-active` 必须手动重刷（`mark(field, value)` 遍历 `.el-settings-segment`），不会自动跟随。
5. **保存按钮要保住 `autoSend` 这类旁路开关**：`asrSaveBtn` 早先就在这踩过（保存把 `autoSend` 打回默认）。这次的 `pSave` 只覆盖 `callMe` / `note`，脾气和长度是点击即存，不会互相打回。

## 八、还没做

- 角色卡只有「脾气 + 长度 + 一句补充」，没有世界书 / 多角色（旧包 `el-role-manager-*` 那套）。
- 聊天偏好没有「温度 / 最大长度」这类采样参数（现在靠人设里的「一次说几句」约束）。
- 手记整理的「至少聊几条」是条数，不是字数；长句短句一视同仁。
- 设置页仍是单页长列表（滚到 2,500 px），分组折叠等 M8 UI 复核再定。
