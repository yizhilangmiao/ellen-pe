# M7 · 自动备份（含大数据量实测）

> 结论：13,929 条记录（message 12,020 / memory 1,504 / journal 404 / emotion 1）→ 组包 **567 ms**、整包 **7,516 KB**、全流程（建文件+写+ commit + 轮换）**1.0–1.5 s**。
> 恢复侧独立验证：换机（`uninstall` → `install`）后从这个包导入，`data-heads 13,924 / data-revisions 13,930` 与备份时一致，manifest 的 `checksum` 与 Python 重算结果逐字相同。
> 轮换：保留 3 份时第 4 次备份会删掉最旧一份（`pruned` 有值、文件夹里只剩 3 个）。

## 一、为什么要做

旧包把「备份」塞在 `EllenArchivePlugin` 的 `backupCall` 里，但两个方法都是 `reject("BACKUP_UNAVAILABLE")` 的桩 —— 界面上有入口，点下去没反应。老大的手机一旦丢/换/双清，十几万条聊天和记忆就没了。

这一块的目标只有一句：**换手机、重装、双清之后，能把相处捡回来。**

## 二、容器格式（复用 EllenArchive v1，不新造格式）

```
"ELLENPK1\n"            9 字节魔数
int32 大端               manifest 长度
manifest (UTF-8 JSON)    {format, version, package:{content, checksum}, files:[]}
各文件字节               按 manifest.files 的顺序逐个追加，长度 = sizeBytes
```

- **附件区已支持**（2026-11-10 收尾）：`files[]` 每项 4 键 `{id, sha256, sizeBytes, mimeType}`；`begin` 先校验清单（id 非空、`sha256` 符合 `[a-f0-9]{64}`、`sizeBytes > 0`，否则 `ARCHIVE_MANIFEST_INVALID`），`write` 按 offset 顺序把字节切到各文件上，**每个文件写满立刻校 sha256**，不符就删掉半成品并回 `ARCHIVE_FILE_MISMATCH`；清单声明了 N 个文件而 commit 时没写满，回 `ARCHIVE_FILE_MISSING`。**web 侧目前仍传空 `files`（见第七节），所以实际产出的包与旧包一致，只是不再"做不到"。**

- `format = "ellen-companion-archive"`、`version = 1`；`package.content.format = "ellen-companion-transfer"`、`formatVersion = 1`。
- `content` 恰好 7 键：`format / formatVersion / packageId / origin{deviceId,platform} / exportedAt / snapshot / media{mode:'metadata-only',requiredIds:[]}`。
- `snapshot = {schemaVersion:1, profiles, records}`，`records` 是**每条记录的最新 revision**（10 键：`id/kind/profileId/revisionId/parents/origin/at/deleted/value/refs`）。
- `checksum` = 对 `content` 做 `JSON.stringify`（`ensure_ascii` 等价、无空格）后的 SHA-256 hex。**顺序敏感**：恢复侧按同一序列化重算，所以字段插入顺序不能改。

## 三、native：`EllenArchivePlugin` 加 `backupCall`

`app\app\src\main\java\cn\ellen\companion2\plugin\EllenArchivePlugin.kt`

| method | 作用 |
|---|---|
| `state` | 读 SharedPreferences `ellen-backup-v1` 的 `state`，顺带 `listGroups()` |
| `configure` | 改 `enabled / intervalDays / retainGroups`，重算 `nextAt` |
| `begin` | 校验 manifest 的 `files[]` → `DocumentsContract.createDocument(…, "艾莲备份-yyyyMMdd-HHmmss.ellenpack")` → 打开输出流 → 写魔数+长度+manifest |
| `write` | 按 offset 顺序追加字节：跨文件边界自动切块，每写满一个附件立刻校 `sha256`（不符 → `ARCHIVE_FILE_MISMATCH` + 删半成品），回 `{offset, bytes, fileIndex, fileBytes}` |
| `commit` | 附件没写满就回 `ARCHIVE_FILE_MISSING` 并清包；写满则关流 → 写 state（`nextAt = now + intervalDays*86400_000`）→ 列组 → 轮换删旧 |
| `abort` | 关流 + 删半截文件 + `lastError` |

- 目录授权：`chooseBackupDirectory` 发 `ACTION_OPEN_DOCUMENT_TREE`（带四个 FLAG，含 `FLAG_GRANT_PERSISTABLE_URI_PERMISSION/PREFIX`），`@ActivityCallback chosenDirectory` 里 `takePersistableUriPermission`，失败也不崩（下次写会报错，界面能看见）。
- 列组不能用 `DocumentsContract.getChildDocuments`（API 30 才有）→ 用 `buildChildDocumentsUriUsingTree` + 查询 `COLUMN_DOCUMENT_ID`。只认 `Regex("艾莲备份-[0-9]{8}-[0-9]{6}\\.ellenpack")`，别人放进同一个文件夹的东西一概不碰。
- 状态字段：`enabled / directory(uri) / directoryName / intervalDays / retainGroups / nextAt / lastCheckAt / lastSuccessAt / lastGroupId / lastName / lastBytes / lastError / fingerprint`；正在写的时候额外带 `writing:true / writingName / writingFiles / writingDone / writingBytes`（`writing` 就是 web 侧 `due()` 判 busy 用的那个字段）。

## 四、web：`core/store/export.js` + `core/backup.js`

- `export.js`：`buildManifest()` 组包（纯内存，不落盘）、`stats()`、`readAll()` 游标全读、`slimRevision()` 瘦身。设置页的「导出资料包」和自动备份共用同一份组包代码。
- `backup.js`：`state() / chooseDirectory() / configure() / fingerprint() / due() / run({force}) / autoRun() / listGroups()`。
- 触发点：App 启动（`syncProactive()` 之后）与 `visibilitychange → visible` 各跑一次 `autoRun()`。
- `due()` 的判定顺序：`unsupported → off → noDirectory → busy → 到日子 → 没变化 → 有变化但未满 12 小时 → 有变化`。
  **为什么有 12 小时闸**：不设的话每聊一句都会写一个 7 MB 的整包。

## 五、实测

造数据（CDP 直插 IndexedDB，`_临时\m7-seed.js`）：message 12,000 / memory 1,500 / journal 400，每批 1,000 条一事务。

| 项 | 值 |
|---|---|
| 库规模 | `data-heads 13,923` / `data-revisions 13,929` |
| `buildManifest()` | **567 ms**，manifest **7,696,183 B（7,516 KB）** |
| 整包文件 | `艾莲备份-20261110-1202.ellenpack` **7,696,196 B**（= manifest + 13 字节头） |
| 全流程 `run()` | 第 1 次 1,285 ms、第 2 次 1,135 ms、第 3 次 1,031 ms |
| 恢复 | `uninstall` → `install` → 从 Documents 选包导入 → `heads 13,924 / revisions 13,930`、`messages` 从 0 变 200（聊天页一次只挂 200 条） |
| 校验 | Python 重算 `sha256(json.dumps(content, ensure_ascii=False, separators=(',',':')))` 与 `package.checksum` **完全一致**（`1dda5aa9c7b8cc5310aca280…`） |
| 轮换 | 保留 2 份时第 3 次备份 → `pruned:["艾莲备份-20261110-121656.ellenpack"]`，`ls` 里确实只剩 2 个 |
| 启动自动备份 | 重装后 `enabled=true`、指纹变化 → 启动即自动生成 `艾莲备份-20261110-130308.ellenpack`（真实数据 23 heads → 20 KB），界面「上次备份 11月10日 13:03 · 0.02 MB · 已有 3」 |
| 附件字节（2026-11-10 补测，模拟器 16448 / CDP 9336） | manifest 声明 1 个 5 B 文件 → `begin` 回 `files:1`、中途 `state` 带 `writing:true / writingFiles:1 / writingDone:0`、`write` 回 `fileIndex:1` → commit **251 B**；`adb pull` 逐字节核对：`"ELLENPK1\n"`(9) + int32BE **233** + manifest + 尾 **5 字节 `hello`**，总长 251 = 246 + 5 |
| 附件校验失败 | 清单写全 0 的 sha256 → `write` 回 `ARCHIVE_FILE_MISMATCH`（消息里带期望 `000000000000…` / 实际 `2cf24dba5fb0…`），`state.writing` 归 `false`、半成品已删、`groups` 不增 |
| 附件缺失 | 声明 2 个只写 1 个就 `commit` → `ARCHIVE_FILE_MISSING`「还有 1 个附件没写完」，同样清包；web 现在的空 `files` 路径仍通（101 B 包） |

## 六、六个坑（都踩了）

1. **游标里不能 `setTimeout(() => c.continue(), 0)` 让帧。** IndexedDB 事务在宏任务之间会提交，之后 `continue()` 抛 `TransactionInactiveError`，Promise 永远不 settle —— 实测 CDP 卡满 300 s 超时，看起来像「组包太慢」，其实是不动了。
2. **文件名精确到分钟会重名。** 同一分钟内连备两次，`createDocument` 会自动变成 `…(1).ellenpack`，而轮换只认标准名 → 那份永远删不掉。改成 `yyyyMMdd-HHmmss`。
3. **`DocumentsContract.getChildDocuments` 是 API 30 才有的**，minSdk 24 编译直接 Unresolved reference。
4. **`due()` 原来先判「没到日子」再判「有变化」**，结果有变化也永远不备（`reason:'notDue'`）。改成到日子优先、有变化走 12 小时闸。
5. **重装后 SharedPreferences 清空但文件夹里的备份还在** → 界面写「还没备份过 · 已有 2」自相矛盾。改成从最新一份的 `at` 反推 `lastSuccessAt`。
6. **`window.confirm` 是原生对话框，不跟 web 层暗色皮肤走**：不加 `alertDialogTheme` 就是白底浅字，导入确认框糊成一片（实测截图拍到了）。已在 `res\values\styles.xml` 加 `EllenAlertDialog`（底 `#23262E`、字 `#F0EDF1`、按钮粉 `#D6A0B4`）+ `colors.xml` 三个颜色。

## 七、还没做

- **附件字节：两侧都通了（见第八节）。** 剩余是对齐：`store/import.js` 的 `files[]` 严格校验 4 键 `{id, sha256, sizeBytes, mimeType}`，而 `store/export.js` 现在写的是 `{id, name, sha256, sizeBytes}`（少 `mimeType`、多 `name`），不改就会在导入时被判 `ARCHIVE_MANIFEST_INVALID`。
- **导入侧的附件只回到附件目录，没有回写媒体库/IndexedDB**：`audio.uri` 存的就是文件名，文件回来就能播；但如果将来媒体改成 blob/引用式，这里还要补一步重建引用。
- **后台定时**：现在只在「启动 / 回前台」检查，App 一直不开就不会备。要真正定时得挂 WorkManager 或精确闹钟（`EllenProactiveScheduler` 已有现成实现）。
- **备份文件夹的提示**：Android 11+ 在选择器里不许选根目录（「无法使用此文件夹」），界面上还没写这句，用户可能以为点坏了。
- **恢复前不提示「要不要先备一份现在的」**：导入是覆盖式的，现在的数据会被顶掉。
- **文件夹换掉后旧文件夹的备份不迁移**（不删也不搬，留在原地）。

## 八、附件字节：两侧落地（2026-11-11）

### 约定

```json
"media": { "mode": "include", "requiredIds": [] },
"files": [ { "id": "voice-1794300000000.wav", "name": "voice-1794300000000.wav",
             "sha256": "<64 hex>", "sizeBytes": 28204 } ]
```

`id` 与 `name` 相同，就是附件文件名；附件本体在 `context.filesDir/attachments/`（`EllenDocuments.save` 写的）。**字节不过 JS 桥**——100 MB base64 过桥必 OOM，所以清单只给名字与摘要，字节由原生按名字从磁盘读。

### 写入侧（`createExport` / `backupBegin` 共用一套）

| 步骤 | 行为 |
|---|---|
| `declaredFiles()` | 校验并**原样返回**清单里的对象（不重建结构：`mimeType` 这类键不能丢，写进容器的清单要和 web 给的逐字节一致） |
| `planAttachments()` | 按 `name` 对磁盘：缺的进 `missing` 并跳过；`sizeBytes` 与磁盘不符 → `FileMismatch`；合计 > 100 MB → `TooLarge` |
| `manifestWith()` | 缺附件时把容器里清单的 `files` 换成「实际写进去的那几个」。**`package.checksum` 只盖 content，不动它**，所以改 files 不会让清单自相矛盾；不换则导入侧「按 files 顺序切 blob」会从缺的那个开始整体错位 |
| `appendAttachments()` | 64 KB 块流式写，每文件独立 `MessageDigest`，边写边更新 `offset / fileIndex / fileWritten` 给 `state.writing*` |

返回体：

- `createExport → { handle, bytes, files, attachments, missing:[...] }`
- `backupBegin → { handle, name, bytes, files, attachments, missing }`
- `backupCommit → { group, pruned, files, missing, state }`

**新增行为**：`backupWrite` 先判 `fileIndex >= files.length()` 直接回 `BACKUP_NOTHING_PENDING`（「清单里的附件已经全部写完，没有待写字节。」）。附件字节全在 `begin` 里由原生读完，web 再喂就是往容器尾巴上多追加字节、包会坏。web 的 `run()` 现在不调 `write`，线上不受影响。

### 导入侧（`pickedImport`）

读完 manifest 后**接着从同一个输入流**按 `files` 顺序切字节（长度由 `sizeBytes` 定，没有分隔符），写 `filesDir/attachments/<name>.part` → 校 sha256 → rename。

- sha256 不符 / 字节不够 / rename 失败 → 该文件跳过、进 `missingFiles`，**整包不失败**（语音可能早被 200 MB 清理删掉，为它让整次恢复失败不值）
- **同名已存在不覆盖**：同 sha → 算 `restoredFiles`；不同 sha → 保留本地、进 `keptFiles`（库里旧记录可能正指着它，覆盖等于改历史）
- 返回 `{ manifestText, restoredFiles, missingFiles:[], keptFiles:[], cancelled }`

`audio.uri` 里存的就是 `voice-<ts>.wav` 这个名字，文件回到附件目录后点语音条自然能播（`EllenDocuments.open({uri})` 按名字找）。

### 待对齐

`store/import.js` 的 `files[]` 严格校验 `['id','sha256','sizeBytes','mimeType']`；`store/export.js` 现在写 `{id,name,sha256,sizeBytes}`。原生按原样透传、不替 web 补键，所以要么 export 补 `mimeType`，要么 import 放宽允许 `name`。
