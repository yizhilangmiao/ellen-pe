# M16 · 语音输入 + 语音消息

> 2026-11-11 · web-chat · 状态：端到端验过（模拟器 127.0.0.1:16448，APK 20:26 构建）

## 一、做了什么

微信式「按住说话」输语音，松手后：录音 → 存成附件 → 本地转写 → 转写文本喂模型 →
气泡里**只显示波形**（右侧粉色/绿色条），文字一个字都不露。
她照常按文本回，所以「听不清」的时候她的回复会跟着走样——这是预期，不是 bug。

## 二、三个新模块（`web/src/app/core/`）

| 文件 | 职责 |
|---|---|
| `voice-input.js` | 手势状态机 + 录音生命周期。`idle → arming(300ms) → recording → (cancelling) → transcribing → idle` |
| `voice-message.js` | `peaksFromWav(base64, 14)` 取波形、`prepareVoice()` 存附件 + 转写 + 兜底文案 |
| `documents.js` | `EllenDocuments` 封装：存/读/删附件，blob URL 缓存与释放 |

常量：`ARM_MS=300`（按住这么久才算说话）、`MIN_MS=700`（更短算误触）、
`MAX_MS=60000`（到点自动收）、`CANCEL_DY=48` + `CANCEL_HYST=8`（上滑取消的迟滞）。

## 三、失败路径（三个都要看得见）

| 情况 | 表现 |
|---|---|
| 系统没给录音权限，弹窗没人点 | arming 超过 600ms 提示「在等系统弹权限…」；松手后浮层变红「要在系统里给录音权限」，1.4s 收起，`phase` 回 `idle` |
| 一直没人点（8s 守卫） | `fail('AUDIO_PERMISSION')`，同上，不会永远停在 arming |
| 录音太短 / 空 | 「太短了，再说一句呗」/「这段录音是空的」，不写库 |
| 转写失败（模拟器静音、没配 ASR） | 文本回落 `（语音 N 秒，没听清）`，`speech.failed=true`，气泡加 `is-asr-failed` 小点；消息照发 |

## 四、落库字段

用户消息多两个字段（`core/state.js` 白名单 + `core/store/messages.js` `toView()` 都已放行）：

```
audio:  { uri, name, bytes, durationMs, peaks[14] }
speech: { text, at, failed }
```

`text` 存转写文本（模型历史用它），但气泡 `renderMessage` 见到 `audio` 就把 `body` 设成 `hidden`，
所以界面上看不到文字。附件走 `EllenDocuments`，重启后照样能播。

## 五、实测（模拟器，pid 31144/31346）

| 项 | 数据 |
|---|---|
| 按住 1.2s | 300ms 内 `is-arming`「按住说话…」→ `is-recording`「松开发送」 |
| 松手 | messages 81→83（用户 + 她），`audio.bytes=28204`、`durationMs=975`、peaks 14 根 |
| 转写 | `ASR_EMPTY_RESULT` → `（语音 1 秒，没听清）`，她回「你嗓子疼就别发语音了。」 |
| 气泡 | 14 根柱、`1″`、`body.hidden=true`、节点文本只有 `1″`（无转写泄漏） |
| 点播 | `<audio>` dur 0.9s，currentTime 0.01→0.88 推进；再点 `paused` |
| 重启后 | `am force-stop` + 重启：4 条语音条都在，点最后一条照样出声（blob 由 `readDocument` 重新取） |
| 权限拒绝 | `pm revoke RECORD_AUDIO` 后按住 → 松手浮层 `is-error`「要在系统里给录音权限」 |
| 上滑取消 | dy ≤ -48 进 `is-cancelling`（红），回到 -40 退出；松手不写库 |

## 七、还没做 / 已知欠账

1. 真机没验：模拟器麦克风是静音源，转写只能拿到 `ASR_EMPTY_RESULT`；真实中文语音的转写质量要在真机看。
2. 多条语音同时播不互斥（点第二条，第一条还在放）；随机语音条（她发的）也一样。
3. `destroy()` 里没有 pause 正在播的 audio（切页会把最后半句播完）。
4. 波形峰值来自 16bit PCM RMS；非 16bit 的 wav 统一给 38（一条平条），真机若出现再修。
5. arming 期间松手现在会提示一次「要在系统里给录音权限」——前提是真的卡在权限上；如果只是录音器慢，会误报一次（概率低，先记着）。
