# 电脑版 → 手机版 功能同步方案模板

> 每同步一个功能就复制这份填一遍。填完再动手，动手前把「风险门」和「验收」两节给老大看。
> 铁律在这里，不靠记：新文件不进 APK；不改宿主 store 结构；不升级 DB 版本；打包通过 ≠ 能跑。

## 一、差异盘点（先填，别猜）

| 环节 | 电脑版 | 手机版 | 结论 |
|---|---|---|---|
| 文档/方案 | 路径 | — | |
| 算法/核心 | 路径 + 关键参数 | 有无 | |
| 存储 | 表/键 + 结构 | 表/键 + 结构 | 能不能复用同一份参数 |
| 生成（模型调用） | gateway | 有无通用入口 | 无入口 → 降级为模板 |
| 接线 | 动作注册 | 桥的 JS 注册表 | |
| UI | 文件 + 定稿视觉 | 有无 | 手机屏小，别照搬桌面悬浮块 |
| 打包 | 改源码树即可 | 只能改已有条目 | 见落点映射 |

## 二、落点映射（手机版只能在已有条目里加东西）

| 要加的东西 | 放哪 | 为什么 |
|---|---|---|
| 页面逻辑模块 | `work/assets/public/ellen-startup-opening.js` 末尾 | 自写 polyfill、非 module、早于 bundle、整文件可替换 |
| 样式 | 模块里运行时 `<style>` 注入 | 少改一个条目，可整体回滚 |
| 数据读写 | 只读 `ellen-mobile-data-v1` | 同源；写入会撞宿主的 revision 语义 |
| 自己的状态 | `localStorage` 单键 | 不与宿主键冲突 |
| 新桥动作 | 打包后能改 bundle，但先问：能不能不用桥 | 桥的 op 表是闭包内的，改它脆 |

**禁止**：往 `_dev_pack.py` 的 manifest 里塞新条目（下次 extract 就丢）；改 storage-worker 的 DB 版本号；改宿主 DOM 结构（SPA 重渲染会掉）。

## 三、分级（先做 A，能不做 B 就不做）

- **A 级 · 纯前端**：注入模块 + 本地状态 + 自绘 UI。零数据风险，一轮可交付。
- **B 级 · 读宿主数据**：只读 IndexedDB / 只调用现有桥动作。要过一次风险门。
- **C 级 · 写宿主数据 / 需要模型**：改 bundle 内闭包、或拿模型 key。先问老大值不值，往往能用 A 级替代（模板 → 电脑端写好导入）。

## 四、风险门（B 级以上必须有，验不通就降级）

| 门 | 怎么验 | 验不通怎么办 |
|---|---|---|
| 能不能读到数据 | 真机 `window.__<mod>.state()` 打 detail | 面板上明说「读不到」，只从今天算 |
| 会不会伤库 | 检查 open 时不带版本、onupgradeneeded 里 abort + deleteDatabase | 绝不 `open(name)` 裸开 |
| 会不会撞宿主渲染 | 自建 fixed 挂点，不 append 到宿主容器里 | 换挂点 |
| 性能 | 首次扫描限一次，之后按需 | 加节流/只扫最近 N 天 |

## 五、验收（真机，缺一项不算完）

见 `验收清单.md`。

## 六、回滚

```powershell
python _patch_phone_<feat>.py --revert     # 撤注入
python _dev_pack.py                        # 回包
pwsh -File _dev_sign.ps1                   # 重签
```

功能自己的状态要能一键清：模块里必须留 `window.__<mod>.debugReset()`，清掉 localStorage 键。
