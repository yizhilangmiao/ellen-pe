## 〇 一句话结论

## 一 先看一组数字（所有改动的依据）

真机截图 864×1920，DPR 2 → CSS 视口 432×960。

| 项 | 实测 | 问题 |
|---|---|---|
| 信纸尺寸 | 398 × **318** CSS px | 只占屏高 **33%**，下方 560px 纯黑 |
| 正文 | 4 行，占纸高 55% | 读 4 秒就完了 |
| 顶栏按钮 | 高 **30px**（14px 字 + 8px padding） | 只有 48dp 的 **62.5%**，且中心离屏顶 57px，**落在下拉通知栏手势带里** |
| 顶栏文字色 | `#9aa3ad` on `#0a0c0f` = 7.6:1 | 数字达标，但 14px 中文在 DPR2 下笔画 1.2px，抗锯齿后**目视有效对比 ≈2.5:1** |
| 未读徽标 | 白字 on `#d6a0b4` = **2.2:1** | 真正不达标的是这个 |
| 纸投影 | `0 22px 46px rgba(0,0,0,.55)` on `#0a0c0f` | **黑叠黑，完全看不见** → 纸是硬切口，像贴纸 |
| 纸渐变 | `#f2eee6 → #e4ded2` | 明度差 6%，肉眼等同纯色块 |

**结论：老板说"不像信"，一半原因不是缺蝴蝶结，是纸只占三分之一屏、边缘没有厚度。**

## 二 信太短（老板第 3 条）

### 根因（已核实）

手机版只渲染模板底稿。`_phone-sync\inject-letter.js` 的 `TEMPLATES` 五阶各是 3–9 行短句拼接，
`ctx.quote` 只是把你的一句原话插进去，**全文 40–60 字**。

电脑版是 `letter-composer.cjs` → `gateway.complete()` 调模型写 1500 字，手机版**没有这一步**。

### 为什么不能简单地在手机上叫模型

已查证手机版的能力边界（`main` / `service` bundle 解码后确认）：

| 想要的 | 能不能 | 依据 |
|---|---|---|
| 页面自己发 HTTP 到 provider | 缺 key | key 存原生侧，页面 `modelProvider` 的 `state` 只回 `baseUrl/model/configured`，`apiKey` 每次关闭即清空 |
| 借 bridge 让原生代写一段文字 | 没有这个动作 | `modelProvider` 只有 `state/cancel/reload/save/saveService/activateService/select/remove/models/test`；`companionLife.journalGenerate` 是写死 prompt 的"手记"，借不了 |
| 改原生加动作 | 改不了 | 打包链只能改 `assets/`，dex 不在 `_dev_pack.py` 的白名单里 |

**所以本期不做真扩写。** 硬做只有一条脏路（在聊天里插一条指令让 AI 写完再抓回来），会污染聊天记录，不做。

### 本期做法：模板扩写 + 弱填空（解决 70%）

- 每阶正文 **600–900 字**（手机阅读 300–500 字/分，正好 1.5–2.5 分钟，是一次"纪念性阅读"的甜点区；
  电脑版 1500 字保留，大屏节奏不同）。
- 每阶留 **6 个填空位**，只填**确定性数据**，不碰聊天原话（避免填错一句吐槽进情书）：

| 占位 | 来源 | 例 |
|---|---|---|
| `{{days}}` | 首条消息到今天的天数 | 42 天 |
| `{{msgs}}` | 累计消息条数 | 318 条 |
| `{{points}}` | 亲密度点数 | 61 |
| `{{first}}` | 第一条用户消息前 12 字 | 「hello」 |
| `{{stageDate}}` | 跨阶日期 | 2026.10.30 |
| `{{stageName}}` | 阶段名 | 熟悉 |

- 语气仍按 `temper` 五档：相识克制、恋人直接。**不要写成情书模板**——艾莲的声线是"我不太会接这种"。

## 三 装饰（老板第 1 条）：照电脑版 1:1 搬，但尺寸按手机重算

电脑版定稿：信封 220×148、封蜡 40px、粉色蝴蝶结、情书 1px 金边 `#c9a86a` + 暖光。
手机信纸宽 398px（电脑信封 220px 的 1.8 倍），**元素全要，尺寸按比例放大但避开正文**。

| 元素 | 电脑版 | 手机版取值 | 位置 |
|---|---|---|---|
| 粉色蝴蝶结 | 信封卡片角上 | 丝带高 **10px** + 结 **28×20px** `#d6a0b4`（结心 `#c98fa5`，上下各 1px `rgba(0,0,0,.08)`） | 横贯纸面，top:14%，结居中 |
| 封蜡 | 40px 圆 | **56px** 圆 `#8c3a44` + 压印「艾」1.5px `#e8d8c8` + `0 2px 4px rgba(0,0,0,.35)` | 落款右侧，外露 8px |
| 金边（情书） | 1px `#c9a86a` | 同值 + `0 0 26px rgba(201,168,106,.22)` | 仅 `lover` 阶 |
| 纸纹 | 无 | SVG `feTurbulence` baseFreq .8，128px 平铺，白噪 .04 + multiply | 全纸（<2KB data-URI） |
| 边缘厚度 | 无 | `0 0 0 1px rgba(255,255,255,.05)` + `inset 0 14px 20px -16px rgba(120,96,64,.30)` + 外描边 `rgba(150,128,96,.5)` | 替代那个看不见的黑投影 |
| 纸外暖光 | 情书暖光 | `0 0 80px rgba(214,160,180,.10)` + `0 28px 60px -24px rgba(0,0,0,.9)` | 让纸从黑底上"浮起来" |
| 日期戳 | 无 | 12px `rgba(110,92,68,.8)`「2026.10.30 · 熟悉」 | 落款上方右对齐 |
| 圆角 | — | 3px → **6px** | 398px 宽上 3px 等于直角 |

**不做**（会掉档，评审已论证）：
- 邮票 —— 语义是"外面寄来的"，和"她亲手递给你"冲突
- 横向折痕 —— 318px 高的纸上像表格线
- 中文手写字体 —— 3–8MB，16px 下糊成一片
- 大花结 + 蕾丝 + 撒花 —— 和"我不太会接这种"的声线直接打架

## 四 按钮（老板第 2 条）：改到底部固定操作条

**位置**：顶部只留 `‹ 返回`（左上，习惯位），`下一封` 移到底部固定条——拇指热区，单手能按。

```
[ ‹ 返回 ]              相识 · 第 1 封              (顶部，48px 高)
─────────────────────────────────────────────
        信 纸（min-height:64vh）
─────────────────────────────────────────────
[  ← 上一封  ]        [   下一封  →   ]        (底部，48px 高，两个等分大按钮)
```

| 项 | 现值 | 新值 |
|---|---|---|
| 按钮高 | 30px | **48px**（达标 48dp） |
| 字号/字重 | 14px / 400 | **15px / 500** |
| 颜色 | `#9aa3ad`（目视 2.5:1） | `#cfd5df`（12.4:1）；主按钮「下一封」用 `#d6a0b4`（8.9:1） |
| 载体 | 无底无边 | 药丸底 `rgba(255,255,255,.06)` + `1px rgba(255,255,255,.10)` 边，圆角 24px |
| 图标 | `‹` `›` 文本字符（8px 宽，笔画是噪音） | **16px SVG 箭头** |
| 顶栏 padding-top | `calc(30px + safe-top)` | `calc(safe-top + 12px)`，按钮中心离开手势带 |
| 不可用时 | 仍然可点 | `opacity:.35` + 文案「已是最近一封」 |
| 未读徽标 | 白字 on `#d6a0b4` = 2.2:1 | 深字 `#3b1f28` = 6.8:1 |

## 五 版式（评审发现，比装饰更伤）

```css
.elbs-paper{ min-height:64vh; display:flex; flex-direction:column; justify-content:center; }
```

- 纸从 318px 拉到 **~614px**（屏高 64%），下方黑从"空缺"变"留白"。
- 短信用**诗行**排法：每行 ≤14 字、行高 2.2、段间 20px；超过 300 字回到行高 1.9 并允许滚动。
- 渐变末端 `#e4ded2 → #ddd5c6`，让右下角真的暗下去。

## 六 读完的出口（评审第 4 条，半天工时，必须加）

现在读完信没有任何后续动作，用户愣在黑屏里；**Android 返回键大概率直接退出 App** → 用户不敢再点第二封。

- 信末 24px 下加两个 48px 高按钮：「**回一句**」（回聊天并预填输入框）/「**收起来**」
- 接管 Android 返回键（`history.pushState` + `popstate`）与下滑关闭
- 软锁「确定现在看？」**只给首封和跨阶信**，第 2 次起 400ms 直接淡入

## 八 下期（0.1.23）：真 AI 扩写需要什么

要动原生，我们改不了，得让上游（或拿到 dex 改造权）加一个动作：

```
action: letters
type:   compose
in:     { stage, points, days, msgs, first, signature, persona, historyExcerpts? }
out:    { body }
约束:   超时 20s；失败必须回落模板；同 stage 只生成一次并缓存
```

页面侧已经准备好对接（`inject-letter.js` 的 `makeLetter()` 是唯一出口，换掉它的数据源即可）。
生成期做 6–10s「艾莲正在写…」（笔尖移动 + 三点），**等待本身是仪式感**。

在原生接口到位之前，模板信 + 弱填空是唯一稳妥路径——不调模型、不断网失败、不写错一句吐槽。

## 九 开发工作怎么分摊（用百炼 / mimo）

软件里**只配 DeepSeek**（应用已内置，用户填一次 key 就到手），不在 App 里接多家。
两家 API 只用于**我做这件事的时候**：

| 活 | 谁干 | 为什么 |
|---|---|---|
| 五阶模板正文初稿（5 × 700 字） | **mimo** | 量最大、可并行试错、降价后最便宜 |
| 模板二审：人设一致性 + 中文长文审美 | **百炼 qwen-max** | 长文润色强，和人设卡对照改 |
| CSS / DOM / 版式 / 交互代码 | **我** | 要动现有注入模块，外部 AI 拿不到上下文 |
| 产品/可用性评审 | **subagent（已跑一轮）** | 已出 12 条排期表，见附录 |
| 打包 / 装机 / 截图验收 | **我** | 只有本机有 MuMu + adb 链 |

这样"分摊"的意思是：**把可并行、可外部化的文案活分包出去，代码和验收我兜住**，
而不是在 App 里加第二家 provider（那只会让用户多动手）。

## 附：评审原始结论（12 条排期表摘要）

只做三件事 → **①正文扩写 + 版式 ②顶栏 48px + `#cfd5df` + 药丸底 ③装饰包**
第四件 **④读完的出口**（半天）也必须加，它决定第二封信会不会被打开。

其余待确认项已在本方案内闭环：发送键/浮钮是否撞（0.1.22 一并调位，浮钮 46→56px）、
键盘弹起遮挡（改用 `bottom:calc(env(safe-area-inset-bottom) + 200px)` 并监听 `visualViewport`）、
信匣列表已读/未读（已实现，补阶段色条与空态文案）。
